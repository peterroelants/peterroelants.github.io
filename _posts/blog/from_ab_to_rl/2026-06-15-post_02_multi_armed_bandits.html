From A/B to RL (2/3): Bandits and Thompson Sampling

Learn and adapt online instead of choosing once at the end.

In the first post, we used a fixed randomized experiment to build posterior beliefs about the success probabilities of two actions. Each action produced a binary outcome. After collecting the data, we used $P(B > A \mid \mathrm{data})$ to ask how likely B was to have the higher expected reward.

Now we keep the same Beta-Bernoulli model, but change the decision problem. At each interaction, the agent chooses an action, observes its binary reward, updates its belief, and uses that updated belief to choose again.

A multi-armed bandit turns this into an online allocation problem: the learner chooses among several actions while learning their rewards, but observes feedback only for the action it selected. This partial-feedback setting is called bandit feedback.

The term multi-armed bandit comes from the image of a row of slot machines, sometimes called one-armed bandits. In bandit language, each option is traditionally called an arm. Following reinforcement-learning terminology, we will mostly use action.

The key shift from a fixed experiment to online allocation is that the learner is no longer only estimating which action is best at the end. It must also decide what to try next while learning.

In RL terms, the learner now has a policy, takes actions, and receives rewards, but there is still no meaningful evolving state. The external state is effectively the same at every interaction; what changes is the agent's internal belief about the actions.

The Toy Problem

Suppose the agent can choose one of three actions at each interaction:

  • Action A
  • Action B
  • Action C

After each choice, the environment returns one immediate binary reward: $1$ for success and $0$ for no success. The success probability $\theta_a$ is therefore also the expected immediate reward of choosing action $a$, which we write as $\mathbb{E}[R \mid a]$:

$$ \mathbb{E}[R \mid a] = 1 \cdot P(R=1 \mid a) + 0 \cdot P(R=0 \mid a) = \theta_a. $$

Because this bandit episode ends after the immediate reward, its action value, in RL terms, is simply the expected reward of choosing action $a$: $\mathbb{E}[R \mid a] = \theta_a$.

The statistical quantity is familiar from the fixed A/B test, but decisions are now made as data arrives. In a fixed experiment, allocation is planned up front and the final decision comes later. In a bandit, the policy chooses an action at each interaction using the feedback collected so far. The goal is cumulative reward: the total reward collected over time.

We will illustrate this with a Bernoulli bandit with three possible actions. Each action has a fixed but hidden success probability. The algorithm never sees those probabilities directly; it only observes binary rewards from the actions it chooses. At each interaction, the policy must balance learning the action values with collecting reward.

From Posterior Beliefs to Online Decisions

The statistical model is almost unchanged from the previous post. Each action $a$ has an unknown success probability $\theta_a$. Since the reward $R_t$ is binary, either $0$ or $1$, $\theta_a$ is also the expected immediate reward of choosing action $a$.

At interaction $t$, the policy first chooses an action, which we write as $a_t$. If $a_t = a$, the reward random variable $R_t$ has success probability $\theta_a$:

$$ P(R_t = 1 \mid a_t = a) = \theta_a, \qquad P(R_t = 0 \mid a_t = a) = 1 - \theta_a. $$

In words, conditional on choosing action $a$, the reward $R_t$ is sampled from a Bernoulli distribution with parameter $\theta_a$:

$$ R_t \mid (a_t = a) \sim \mathrm{Bernoulli}(\theta_a). $$

For each action, we start with a Beta prior on its unknown success probability:

$$ \theta_a \sim \mathrm{Beta}(1, 1). $$

Let $(\alpha_a, \beta_a)$ denote the current Beta parameters for each action. After choosing action $a_t$ and observing reward $r_t \in \{0, 1\}$, we update only that action:

$$ \alpha_{a_t} \leftarrow \alpha_{a_t} + r_t, \qquad \beta_{a_t} \leftarrow \beta_{a_t} + (1 - r_t). $$

This is the same Beta-Bernoulli update as in the first post, applied one interaction at a time. The posterior from one step becomes the prior for the next. For a standalone explanation of why this two-count update fits sequential binary feedback, see Beta Priors and Pólya Urns for Binary Decisions.

Online Updates and Cumulative Reward

The model has not changed; the objective has. The goal is no longer just to identify the best action at the end. The learner must also collect as much cumulative reward as possible while it learns.

Because each interaction is one-step, the reward for one interaction is just the immediate binary outcome. If we write that reward as $r_t$, then $r_t = 1$ for success and $r_t = 0$ for no success. Across the whole run, the objective is to maximize cumulative reward:

$$ \sum_{t=1}^T r_t. $$

In this binary setup, the action value is the expected immediate reward. That expected reward is $\theta_a$, the action's hidden success probability. Sampling a plausible $\theta_a$ is therefore the same as sampling a plausible action value.

Policy and Exploration

To act online, we need a policy: a rule for selecting the next action. In standard RL notation, a policy is often written as $\pi(a \mid s)$, a distribution over actions $a$ that can be taken from a state $s$. Because the external state is always the same state $s_0$, we write the policy as $\pi_t(a)$ instead of $\pi_t(a \mid s_0)$. What changes over time is the agent's posterior belief about the actions.

A bandit policy must balance the exploration-exploitation dilemma. At one extreme, a greedy policy always chooses the action that currently looks best. It uses the evidence collected so far, but may stop trying underexplored actions too early and miss one that would have been better. At the other extreme, a uniformly random policy keeps exploring every action but never uses what it has learned to improve cumulative reward.

A common compromise is an $\varepsilon$-greedy policy: most of the time choose the currently best-looking action, and with probability $\varepsilon$ explore by choosing a random action.

Here we use probability matching. We already model posterior uncertainty over each action's expected reward. In the first post, that uncertainty gave us $P(B > A \mid \mathrm{data})$. Here, the same comparison drives action selection: an action is chosen in proportion to the posterior probability that it is best. With $K$ actions, we ask this question for every action: under the current posterior, how likely is this action to have the highest expected reward? Here, $\mathrm{data}_t$ denotes all action-reward observations available before interaction $t$.

$$ \pi_t(a) = P\!\left(\theta_a > \theta_j \;\; \text{for every other action } j \mid \mathrm{data}_t\right). $$

In other words, $\pi_t(a)$ is the posterior probability that action $a$ has the highest expected reward. Because this is a one-step binary setup, the action with the highest expected reward is also the action with the highest action value.

This rule turns the posterior probabilities into a policy distribution: choose each action with probability $\pi_t(a)$ on the next interaction. This is the idea Thompson described in 1933: use the current probability that each option is best to guide allocation as more evidence arrives, instead of waiting for one final decision. Exploration comes from posterior uncertainty rather than a fixed $\varepsilon$, so an underexplored action can still be chosen when the posterior leaves a meaningful chance that it is best.

Online Learning with Bandit Feedback

With bandit feedback, we observe the reward of the action we chose, but not the rewards we would have observed had we chosen the other actions. Each interaction is therefore both a chance to learn and a chance to earn reward.

This is still a one-state, immediate-reward problem: the simplest RL-like setting. The agent chooses actions and receives rewards, but there is no evolving external state. Each interaction ends after the immediate reward; what changes over time is the learner's information about the actions.

Thompson Sampling as Posterior Sampling

The policy distribution

$$ \pi_t(a) = P\!\left(\theta_a > \theta_j \;\; \text{for every other action } j \mid \mathrm{data}_t\right) $$

can be difficult to compute exactly. For choosing one action, however, we do not need to estimate the full distribution.

In the first post, we estimated $P(B > A \mid \mathrm{data})$ by sampling from the posterior. We drew many plausible expected rewards, $\tilde\theta_A$ and $\tilde\theta_B$, counted how often $\tilde\theta_B$ was higher, and used that empirical frequency as a Monte Carlo estimate.

Repeated posterior comparisons would estimate $\pi_t(a)$. Drawing one plausible value from each action's posterior and choosing the largest draw produces one exact sample from the probability-matching policy. For a single interaction, we write those draws as $\tilde\theta_i$ and choose $A_t = \arg\max_i \tilde\theta_i$.

Written in probability notation, the selected action has the policy distribution because selecting action $a$ is exactly the event that $a$ has the largest sampled expected reward:

$$ P(A_t = a \mid \mathrm{data}_t) = P\!\left(\tilde\theta_a > \tilde\theta_j \;\; \text{for every other action } j \mid \mathrm{data}_t\right) = \pi_t(a). $$

Repeated sample-and-compare draws would reveal the policy distribution, but a single draw is already one valid sample from it. That is the key idea behind Thompson sampling: use current posterior uncertainty to choose actions while evidence accumulates, instead of waiting for one final decision.

Equivalently, Thompson sampling is a one-sample Monte Carlo implementation of probability matching. It draws one plausible action value for each action and acts on the largest draw instead of estimating the whole policy distribution.

The Thompson sampling algorithm works as follows:

  1. sample one plausible expected reward $\tilde{\theta}_i$ from each action's current posterior,
  2. read each sampled expected reward as a sampled action value,
  3. choose the action with the largest sampled value,
  4. observe one binary reward,
  5. update only the chosen action.

If we repeated steps 1–3 many times without updating, the action frequencies would approach $\pi_t(a)$. In the actual algorithm, we make one draw per interaction, then observe the feedback and update the chosen action before the next draw.

In this one-step setting, the sampled $\tilde{\theta}_i$ values are sampled action values: plausible average rewards for each action, not possible next binary outcomes.

The simulations below make these ideas concrete. We will watch the posteriors evolve, see the induced policy concentrate on the best action, and track reward and expected regret along the way.

# Define bandit records, posterior updates, and probability-matching helpers.
@dataclass(frozen=True)
class BanditInteraction:
    """Observed feedback and expected regret from one bandit interaction."""

    action: int
    reward: int
    expected_regret: float


def beta_posterior_means(alpha: FloatArray, beta: FloatArray) -> FloatArray:
    """Return the posterior mean expected reward of each action."""
    return alpha / (alpha + beta)


def update_beta_bernoulli_posterior(
    alpha: FloatArray,
    beta: FloatArray,
    action: int,
    reward: int,
) -> tuple[FloatArray, FloatArray]:
    """Update only the chosen action's Beta posterior after binary reward feedback."""
    updated_alpha = alpha.copy()
    updated_beta = beta.copy()
    updated_alpha[action] += reward
    updated_beta[action] += 1 - reward
    return updated_alpha, updated_beta


def estimate_probability_each_action_is_best(
    alpha: FloatArray,
    beta: FloatArray,
    rng: np.random.Generator,
    size: int = 50_000,
) -> FloatArray:
    """Monte Carlo estimate of the probability-matching policy.

    The estimate samples plausible expected rewards from each action's Beta posterior
    and returns the empirical frequency with which each action has the largest sample.
    """
    sampled_action_values = rng.beta(alpha, beta, size=(size, len(alpha)))
    winning_actions = np.argmax(sampled_action_values, axis=1)
    return np.bincount(winning_actions, minlength=len(alpha)) / size

# Run Thompson sampling for repeated bandit interactions.
n_steps = 1000
steps = np.arange(1, n_steps + 1)
bandit_rng = np.random.default_rng(202604243)

# Initialize one Beta posterior per action.
alpha = np.ones(n_actions, dtype=float)
beta = np.ones(n_actions, dtype=float)

interaction_log: list[BanditInteraction] = []
posterior_history: dict[int, tuple[FloatArray, FloatArray]] = {}
checkpoints = [1, 10, 50, 200, 500, 1000]

# Run Thompson sampling as repeated agent-environment interaction.
for step in steps:
    # Sample one plausible expected reward for each action from its posterior.
    sampled_action_values = bandit_rng.beta(alpha, beta)

    # Choose the action with the highest sampled value.
    action = int(np.argmax(sampled_action_values))

    # Observe binary feedback from the selected action's hidden success probability.
    reward = int(bandit_rng.binomial(n=1, p=true_success_probabilities[action]))

    # Update only the selected action's Beta posterior.
    alpha, beta = update_beta_bernoulli_posterior(
        alpha=alpha,
        beta=beta,
        action=action,
        reward=reward,
    )

    # Log feedback and instantaneous expected regret for later summaries.
    instant_expected_regret = float(np.max(true_success_probabilities) - true_success_probabilities[action])
    interaction_log.append(BanditInteraction(action=action, reward=reward, expected_regret=instant_expected_regret))

    # Keep posterior snapshots for the checkpoint visualizations.
    if step in checkpoints:
        posterior_history[step] = (alpha.copy(), beta.copy())

Posterior Evolution

The Bayesian update is the same as in the first post, but here it drives the online decision rule. Each action has a Beta posterior over its unknown expected reward $\theta_a$. When a chosen action produces reward $1$, its posterior shifts to the right; when it produces reward $0$, it shifts to the left.

When reading these curves, focus on two things:

  • the location of the curve tells us which expected rewards currently look plausible,
  • the width of the curve tells us how uncertain we still are about that action value.

Frequently chosen actions accumulate evidence quickly, so their posteriors become narrower. Less frequently chosen actions remain more diffuse. Thompson sampling uses that difference in uncertainty: uncertain actions can still be explored, while well-performing and well-measured actions are exploited more often.

Each panel shows the posterior over every action's expected reward at a different point in the run. The dashed lines mark the hidden true expected rewards used to generate the simulation, so we can see whether the posteriors are moving in the right direction. Only the chosen action is updated after each interaction; the others stay where they are until they are chosen again.

Reward, Expected Regret, and Action Allocation

A bandit should not keep allocating equally forever. It starts uncertain, explores several actions, and then shifts more interactions toward the actions that continue to look promising. That is the main behavioral difference from a fixed experiment.

There are three useful views of the run:

  • Cumulative reward: the reward actually collected; this is the run-level quantity the bandit tries to maximize.
  • Cumulative expected regret: expected reward left uncollected compared with an oracle that always picked the best action.
  • Action allocation: how the algorithm shifted choices over time.

In the simulation, the reward at interaction $t$ is $r_t$: $1$ for success and $0$ for no success. The cumulative reward $\sum_t r_t$ is the total reward collected during learning. Because we know the hidden true action values, we can also compute the expected regret of the selected action sequence. If $\theta^*$ is the best action's true expected reward and we chose action $a_t$, the expected regret at interaction $t$ is $\theta^* - \theta_{a_t}$. This compares expected rewards, not the realized reward from this run with the realized reward from another run. Summing over interactions gives cumulative expected regret, the total expected reward shortfall relative to the oracle.

For comparison, we also use a simple uniform baseline that splits allocation evenly across the three actions. This is a fixed-experiment reference point: keep testing evenly and do not adapt. The uniform and oracle reward lines are expected-reference curves, not realized alternative runs. We can plot expected regret only because this is a simulation and we know the hidden true action values. In a real bandit deployment, expected regret is not directly observable.

One practical caveat: adaptively collected bandit data should not be analyzed as if it came from a fixed randomized experiment. The policy that generated the data is part of the data-generating process. If we want to make causal or off-policy claims from logged bandit data, we need to account for that policy, usually by logging action probabilities and keeping enough exploration for alternative actions to remain observable.

Summary

In the first post, Bayesian posterior uncertainty was a final decision aid. Here, the bandit uses the same kind of belief online.

At each interaction:

  • the policy chooses one action using the current posterior belief,
  • the environment returns an immediate binary reward for that chosen action only,
  • the learner updates only the chosen action's Beta posterior,
  • the updated posterior becomes the input to the next action choice.

The key shift from a fixed A/B test is that the posterior is no longer used only after data collection. It becomes part of the action loop. Probability matching turns posterior probabilities into a policy distribution, so actions that are still plausibly best retain some chance of being tried. Thompson sampling draws one plausible action value for each action, chooses the largest draw, observes the reward, and updates the chosen action. It samples plausible average rewards, not possible next binary outcomes.

This post moves us from fixed experiments to online learning with actions, rewards, an adaptive policy, bandit feedback, and cumulative reward. It is still only a small step toward RL: there is no evolving external state or delayed credit assignment yet. We will explore both in the next post.
